    What this does

    MeshCore can only carry short text messages. Meshpix squeezes a picture down to a few hundred bytes, turns those bytes into text, and splits the text into message-sized pieces. You send the pieces with the normal MeshCore app. Your friend pastes them into this page and gets the picture back. Nobody installs anything, and nothing leaves your device: all the work happens in the browser.

    Expect thumbnail-sized pictures. A 64-pixel photo usually fits in 2 to 4 messages.

    Sending

    1. Pick a picture, then crop it to the part that matters. Small subjects that fill the frame survive best.
    2. Choose a preset, or set the size and quality yourself. Turn on Fit into a set number of messages if you have a message budget.
    3. Optionally copy the heads-up message and send it first, so your friend knows what's coming.
    4. Press Copy message 1, paste it into MeshCore, send it. Repeat until every tile is filled.

    Receiving

    1. Copy each message that starts with ~m or ~b from MeshCore.
    2. Paste it into the Receive tab. The picture draws from the top down as pieces arrive, and anything received is remembered in this browser if you leave and come back.
    3. If a message never arrives, any recovery message can stand in for it. The tile strip shows what's still missing.
    4. Save the picture, or copy it into another app.

    Being a good neighbour on the mesh

    Every message on a public channel gets repeated by each repeater that hears it, and the channel is shared airtime. A few habits keep the mesh usable for everyone:

    • Send pictures as a direct message or on a private channel, not on Public.
    • Keep it to a handful of messages. The page warns you past 8.
    • Leave a gap between messages. The countdown next to the copy button suggests one based on your radio settings and nearby repeaters.

    Photo or pixel art?

    Photo uses a JPEG-like method tuned for tiny pictures: it keeps gradients and faces recognisable at very low byte counts. Pixel art reduces the picture to a small set of exact colours and is better for logos, drawings, maps, screenshots, QR-like graphics and emoji-style icons, where crisp edges matter more than shading.

    Troubleshooting

    • A message isn't recognised. It was probably cut short. Lower Characters per message under Message settings and send again.
    • “Checksum mismatch.” Two different pictures got mixed, or a message was edited. Remove the picture and paste again.
    • Clipboard buttons don't work. Some browsers block them inside embedded pages. Select the text and copy or paste it by hand; long-press works on phones.

    Format, for the curious

    Every message is a 7-character header followed by the data:

    ~mFT0365sd.Fb9HWWWpp5Kc4cxPbZ…
    CharactersMeaning
    ~Marker that starts every Meshpix message
    mAlphabet: m is Compact (base 85, 4 bytes in 5 characters), b is Base64
    FTPicture id, two random characters
    0This message's index, base 62
    3k, the number of picture messages
    6n, the total number of messages including recovery
    the restData, the same length in every message of a picture

    The n − k recovery messages are a Reed–Solomon erasure code over GF(256) built from a Cauchy matrix, so any k of the n messages rebuild the picture. Inside is a small container: a version and codec byte, the total length, the caption, the image data and a CRC-16.

    CodecHow it works
    PhotoYCbCr with 4:2:0 colour, 8×8 DCT, JPEG quantisation tables scaled by quality, then an adaptive binary arithmetic coder with context modelling of DC differences, coefficient positions and magnitudes. No Huffman tables or headers to pay for, which is what normally makes JPEG useless below 1 KB.
    Pixel artMedian-cut plus k-means palette (stored as RGB565), optional ordered or error-diffusion dithering, then each pixel coded as “same as left”, “same as above” or an explicit colour, with probabilities learned from the neighbouring pixels.
